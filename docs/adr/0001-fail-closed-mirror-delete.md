# ADR-0001：抓取失败时必须 fail-closed，绝不触发 mirror-delete

- 状态：已接受
- 日期：2026-10-08
- 背景事故：2026-09-28 01:17，`github.token` 失效导致 GitHub API 返回
  `401 Bad credentials`，脚本把「读不到仓库列表」当成「仓库全被删除」，
  一次性从 OpenList 删除了两个账号下全部 25 个仓库目录。

## 背景

同步引擎有两处删除逻辑（mirror-delete，`sync.mirror_delete: true` 为默认值）：

1. 仓库级：manifest 里记录过、但本次 GitHub 仓库列表里没有的仓库 → 删除
   OpenList 上的整个仓库目录；
2. 文件级：manifest 里记录过、但本次文件树里没有的文件 → 删除该文件。

两者原本都建立在同一个假设上：**「本次没列出来的东西 = 上游已删除」**。

但 `GitHubClient.get_repos()` 在非 200 响应时只打了一条 error 日志就
`break`，然后返回累积到的（通常是空的）列表。于是「请求失败」和「账号真的
没有仓库」产生了完全相同的返回值 `[]`，调用方无法区分，直接走了删除分支。

事故的触发条件很普通：token 过期、被撤销、粘贴时带了空白字符，或者 GitHub
临时 5xx。这类事情一定会再发生，所以必须在设计上消除「失败 = 空」的歧义。

## 决策

**mirror-delete 只在「正向的存在性证据」下执行**，即：一次完整、成功
（HTTP 200）的列表请求，且该列表里确实没有这一项。

具体规则：

1. **空结果只能来自 200。** `fetch_repos()` / `get_file_tree()` 在任何非
   200、网络异常、重试耗尽、payload 类型不符的情况下抛出
   `GitHubAPIError`，绝不返回空列表/空树。空列表从此只有一个含义——账号
   真的没有仓库。
2. **分页必须完整。** 分页中途失败同样抛异常，不再保留「已成功的前几页」。
   部分列表比空列表更危险：它看起来正常，却会让后面几页的仓库被判为已删除。
3. **截断的树不构成证据。** GitHub 以 `truncated: true` 返回被截断的文件树
   时，跳过该仓库的文件级删除并报错（大仓库场景）。
4. **本地配置不能导致删除。** 仓库级删除的判据集合是「GitHub 返回的全部
   owner 仓库（含 fork 与 private）」，而不是「过滤后要同步的仓库」。因此
   黑名单/白名单改动、`sync_private_repos` 开关、fork 跳过都不会再删数据。
   manifest 会记录仓库可见性，当私有仓库当前不可见（无 token / token 被拒 /
   关闭私有同步）时，即使它不在列表里也保留。
5. **删除有总量护栏。** 当单次删除量 `>= delete_guard_min_count`（默认 5）
   且 `> delete_guard_ratio * 已知条目数`（默认 0.5）时，本次删除全部取消并
   报错。确认 GitHub 侧无误后可重跑，或把 ratio 设为 1.0 关闭护栏。
6. **删除失败要留痕。** 只有 OpenList 确认删除成功后，才从 manifest 移除
   条目；失败则保留，下个周期重试，避免静默分叉。
7. **失败必须被看见。** 账号级失败进入周期汇总的 `errors`，写入
   `SyncState.last_error`，在面板顶部显示；`--once` 模式以退出码 1 结束。

## 后果

- 正面：任何 GitHub 读取故障都退化为「本轮不同步、不删除」，而不是数据丢失。
  故障可见、可诊断。
- 正面：`state.deleted_files` 与 summary 不再重复计数（原实现里
  `_cleanup_stale_repos` 自增一次、调用方再加一次）。
- 代价：删除行为更保守。全量清空账号（20 个仓库真的都被删了）会被护栏拦下，
  需要人工确认或调高 `delete_guard_ratio`。这是有意的取舍。
- 代价：`allow_unauthenticated_fallback` 默认关闭——token 失效时公开仓库也
  会停止同步（但不会删除任何东西），用户必须去修 token。选择“响亮地失败”
  而不是“安静地降级”。
- 兼容性：manifest 新增可选的 `private` 字段，旧文件无需迁移；仓库 key 的
  owner/repo 匹配改为大小写不敏感（GitHub 用户名本就不区分大小写）。
- 接口变更：`get_repos()` 由 `fetch_repos()` 取代并返回 `RepoInfo`（不再在
  客户端内部过滤 fork/private）；`get_file_tree()` 返回 `FileTree`
  （带 `truncated`/`complete`）。

## 被否决的方案

- **「非 200 就返回空列表，但调用方判断一下」**：只要返回值存在歧义，任何
  一处漏判就再次造成全量删除。歧义必须在类型层面消除。
- **「只在删除前调用一次 `/rate_limit` 预检」**：预检通过不代表后续分页
  都成功，无法覆盖 5xx 与截断。
- **「保留全部文件、只做上传不做删除」**：放弃 mirror 语义，OpenList 会
  永久残留已删除文件，与项目目的不符。
- **「默认 `mirror_delete: false`」**：把默认值改掉只是降低概率，不改变
  「失败 = 空」的根因；且用户明确需要镜像删除。
